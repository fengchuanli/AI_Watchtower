# AI Watchtower 版权安全规则

这份规则用于降低 AI Watchtower 的内容版权风险，同时保留本站最重要的价值：帮助中文读者看懂 AI 新闻、判断趋势、知道下一步该关注什么。

这不是法律意见，而是项目内部的内容安全边界。遇到高风险来源、付费墙内容、转载限制、争议性媒体报道或商业化发布前，应继续寻求专业法律意见。

## 核心原则

AI Watchtower 不做“原文中文版替代品”。

本站可以做：

- 记录新闻标题、来源、发布时间和原始链接。
- 用很短的中文说明“发生了什么”。
- 解释这件事为什么值得关注。
- 写 AI Watchtower 自己的趋势判断、读者使用方法、核验边界和下一步观察点。
- 引导读者点击原始来源查看完整事实、采访细节、图表、上下文和原文措辞。

本站不做：

- 复制全文或接近全文。
- 把媒体文章逐段改写成中文长文。
- 复述大量采访细节、背景段落、图表数据或独家叙述。
- 让用户看完本站后完全不需要访问原始来源。
- 绕过付费墙、登录墙或明确禁止抓取的访问限制。
- 抓取、保存、总结或改写付费墙、登录墙后的正文内容，即使技术上能看到部分正文也不允许。

## 来源分级写法

### 1. RSS 或官方摘要

风险较低，但仍要克制。

允许：

- 标题。
- 来源名称。
- 原文链接。
- 1 到 3 行中文摘要。
- AI Watchtower 自己的趋势判断和核验边界。

避免：

- 把 RSS 摘要扩写成完整报道。
- 批量复刻来源站的全部信息结构。

### 2. 官方公告、产品博客、研究页面

可以比媒体来源写得更完整，但仍不要复制原文。

适合写：

- 官方直接宣布了什么。
- 产品、模型、政策或研究的关键变化。
- 这对普通读者、开发者、企业或监管观察者意味着什么。
- 来源没有证明什么。

避免：

- 复制官方页面的大段解释。
- 翻译整段原文。
- 使用官方营销语气作为本站结论。

### 3. 媒体报道

这是最需要克制的来源类型。

允许：

- 只抽取最小必要事实：谁、做了什么、何时、金额或对象是什么。
- 1 到 2 句中文事件说明。
- 明确来源是媒体背景，不是官方确认。
- 重点写本站自己的趋势判断、风险边界、下一步核验对象。

避免：

- 写 200 字以上的媒体文章替代摘要。
- 复述采访、独家细节、长背景、市场分析或文章结构。
- 把单一媒体报道包装成已确认事实。
- 让详情页成为“读完就不用点媒体原文”的版本。

### 4. 社区讨论、社交平台、论坛

只能作为发现线索。

允许：

- 标记为待核验信号。
- 说明社区正在讨论什么。
- 指向需要等待的官方、论文、监管或可靠媒体确认。

避免：

- 当作事实发布。
- 把截图、爆料、匿名转述写成新闻。

## 推荐详情页结构

为了同时降低风险和保持可读性，详情页应优先使用这个结构：

1. **最小事实**：来源直接支持的事实，尽量短。
2. **本站解读**：AI Watchtower 对这件事的理解框架。
3. **趋势判断**：这件事放到 AI 产业变化里意味着什么。
4. **为什么值得关注**：普通中文读者该从中得到什么判断。
5. **还需要看原文确认什么**：完整事实、采访细节、图表、原始措辞和上下文。

其中“最小事实”应保持短；“本站解读”和“趋势判断”可以承担主要阅读价值。

## 字数和替代性边界

默认上限：

- 首页事件说明：1 到 2 句。
- 媒体来源详情页的来源事实：不超过 120 个中文字。
- 官方来源详情页的来源事实：不超过 220 个中文字。
- 趋势判断、读者影响、核验边界可以更长，但必须明显是 AI Watchtower 的原创分析，而不是原文复述。

判断标准：

- 如果读者看完本站后仍需要点原始来源确认完整事实，风险较低。
- 如果读者看完本站后已经不需要原始来源，风险升高。
- 如果本站内容像一篇媒体文章的中文改写，必须删减。

## 自动化抓取规则

新闻抓取任务必须遵守：

- 半自动采集或批量候选 URL 进入起草前，先用 `docs/candidate-source-checklist.md` 筛掉付费墙、登录墙、重复 URL、来源角色不清和无法支持详情页简报的候选。
- 优先 RSS、官方公告、官方博客、论文、监管原文和可靠媒体的公开页面。
- 禁止抓取付费墙或登录墙标题以外内容。对于付费媒体，只允许使用公开可见的标题、公开摘要、来源名称、发布时间和链接。
- 即使技术上可以看到部分正文，也不得抓取、保存、总结或改写付费墙、登录墙后的正文内容。
- 不保存或展示全文。
- 不得把媒体全文、大段正文或多个段落直接输入 AI，让 AI 生成中文改写版、扩写版或摘要版。
- AI 只能基于最小事实、标题、公开摘要和人工提取的要点生成本站解读。
- 对媒体来源只提取最小事实，再写本站解读。
- 保留原始来源链接，并把它标记为完整事实入口。
- 在 `provenance`、`claimBoundary`、`nextCheck` 中写清楚来源能证明什么、不能证明什么、还要看哪里。

## 原文依赖度

每条新闻建议增加 `originalDependency` 字段，用来说明读者是否必须阅读原文才能掌握完整事实。

可选值：

- `must-read`：必须阅读原文。媒体来源默认使用这个值，页面必须明确说明完整事实、采访细节、图表和上下文请阅读原文。
- `recommended`：建议阅读原文。适用于官方公告、论文或监管文本，本站可以解释重点，但原文仍是事实入口。
- `optional`：可选阅读原文。仅适用于非常短的官方状态更新、公开 changelog 或本站原创整理。

默认规则：

- `sourceType: "reliable_media"` 或 `sourceType: "media_report"` 时，`originalDependency` 默认应为 `must-read`。
- 详情页应把 `must-read` 显示为“完整事实请读原文”，而不是把本站内容写成替代阅读。

## 原文引用上限

默认不直接引用原文。确有必要引用时：

- 必须使用引号或引用样式。
- 单条内容尽量不超过一句。
- 不连续引用多个句子。
- 不引用文章最有价值的独家表达、标题党式金句或完整结论段。
- 必须附来源链接。
- 不引用付费墙、登录墙后的正文。

## 图片与图表规则

禁止：

- 保存媒体文章配图。
- 转载付费媒体截图。
- 复制媒体制作的图表。
- 批量缓存外部网站图片。
- 使用来源站图片来替代读者访问原文。

允许：

- 使用官方明确允许转载的 press kit 图片，并附来源。
- 使用论文、官方博客中明确允许引用的图表，并附来源和上下文。
- 自己制作趋势图、时间线、结构图和新闻全貌解析图。
- 必要时使用短截图说明界面变化，但必须控制范围、附来源，并避免截取媒体正文或付费内容。

## 来源可信度与声明状态

建议每条内容逐步增加结构化字段：

```json
{
  "sourceType": "official",
  "sourceReliability": "high",
  "claimStatus": "confirmed"
}
```

`sourceType` 可选：

- `official`
- `research`
- `regulator`
- `reliable_media`
- `media_report`
- `community_signal`

`sourceReliability` 可选：

- `high`
- `medium`
- `low`
- `unknown`

`claimStatus` 可选：

- `confirmed`
- `reported`
- `rumored`
- `disputed`
- `unclear`

页面应把状态说清楚，例如：`状态：媒体报道，尚待官方确认`。这样可以降低误导风险，也能帮助读者知道哪些内容只是信号。

## 删除与更正规则

如果来源方、权利人或用户提出内容版权投诉，应：

1. 先临时下架相关页面或隐藏争议段落。
2. 检查是否存在过度摘要、替代原文、错误引用、图片转载或付费墙内容使用。
3. 必要时改成标题、来源、链接和极短说明。
4. 记录处理时间、修改内容和处理原因。
5. 对同类来源补充规则或验证，避免重复发生。

## 商业化前复查

以下情况必须重新评估版权安全规则，并考虑寻求专业法律意见：

- 加入广告。
- 加入付费订阅。
- 批量抓取媒体内容。
- 对外提供新闻 API。
- 允许用户不访问原站也能完成阅读。
- 使用媒体内容训练模型或生成数据库。
- 扩大到公开营销、商业合作或明显超过个人/小范围阅读场景。

## 发布前检查问题

发布前逐条问：

1. 这条内容有没有复制或接近复制原文？
2. 这条内容是否像原文的完整中文替代版？
3. 媒体来源事实是否已经压缩到最小必要信息？
4. 趋势判断是否是本站自己的分析，而不是媒体分析的改写？
5. 用户是否仍然需要点击原文查看完整事实和上下文？
6. 原始来源链接是否清楚可见？
7. 是否错误使用了付费墙、登录墙正文、媒体图片、截图或图表？
8. 是否需要设置 `originalDependency: "must-read"` 并提示读者阅读原文？

如果第 1 或第 2 个问题答案是“是”，不要发布。
