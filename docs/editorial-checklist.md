# AI 新闻编辑核对清单

这份清单用于人工编辑或自动化写入 `data/news.json` 前的内容审核。目标不是追求最快发布，而是让标题、摘要、来源和编辑判断都能被读者复核。

## 一、先确认内容状态

每条内容只能进入以下一种状态：

- **已核验**：中心事实已由所引用的原始来源支持，标题和摘要没有超出来源结论。
- **待核验信号**：有明确来源，但关键事实仍缺少官方确认、交叉来源或必要上下文。
- **不发布**：只有传闻、截图、匿名转述、无法访问的来源，或中心事实与来源不一致。

示例数据不得标记为“已核验”。社区热度、搜索排名和单一媒体转述也不能自动升级为已核验事实。

## 二、逐条核对

### 1. 中心事实

- 用一句话写出这条内容真正声称发生了什么。
- 确认标题、摘要和趋势判断没有混成同一个事实陈述。
- 删除“全面领先”“行业首次”“普遍采用”等来源无法直接支持的绝对化措辞。

### 2. 原始来源

- 优先链接公司公告、产品文档、论文、监管原文或交易参与方声明。
- 媒体可补充背景，但涉及模型发布、价格、政策、融资和公司声明时，应继续寻找原始确认。
- 社区帖子只作为发现入口，不作为中心事实的唯一证据。

### 3. 时间与范围

- 核对发布日期、事件发生日期和页面更新日期，避免把旧闻写成当天变化。
- 政策内容必须注明适用地区、生效时间和执行主体。
- 产品与模型内容必须区分测试、预览、正式上线以及可用地区或用户范围。

### 4. 数字与比较

- 记录数字对应的单位、样本、时间窗口和比较基线。
- 榜单、评测和成本结论必须保留测试条件，不能从单一指标推导整体优劣。
- 融资金额、估值、用户量和收入数据至少需要原始声明或可靠交叉来源。

### 5. 编辑判断

- `trend` 说明可观察的方向，不把推测写成已发生事实。
- `whyRanked` 解释为什么值得关注，不用“热度高”代替证据。
- `impact` 说明可能影响谁、影响什么，并避免投资、法律或医疗结论。
- `nextCheck` 必须给出下一步可执行的核对对象，例如官方文档、客户案例、法规原文或实验基线。

### 6. 来源展示

- `sourceId` 必须存在于 `data/sources.json`。
- `sourceUrl` 应尽量指向支持中心事实的具体页面，而不是只链接来源首页。
- `trustLevel` 只描述来源类型；事实是否确认由 `verificationStatus` 单独表达。
- `provenance` 应说明来源能证明什么、不能证明什么。

## 三、发布前决策

满足以下条件才可标记为“已核验”：

1. 中心事实与原始来源一致。
2. 标题和摘要没有扩大来源结论。
3. 时间、地区、对象和产品阶段已经明确。
4. 关键数字具备单位、口径和可追溯出处。
5. 趋势判断与事实陈述已经清楚分开。

任一关键条件缺失时，保留为待核验信号并写明 `nextCheck`；来源不可追溯或存在明显矛盾时，不进入首页新闻流。

## 四、提交前检查

```bash
node --check app.js
node scripts/validate-data.mjs
node scripts/validate-site.mjs
```

自动校验只能发现结构错误，不能代替来源阅读和事实判断。
