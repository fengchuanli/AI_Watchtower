# Question Routing（質問から検索対象を推定する）

## 背景

Azure AI Search で「来源可信度怎么判断」を全 source から検索すると、上位 5 件がすべて過去ニュースになりました。
ニュース chunk には「来源:」「来源角色:」「可信层级:」「核验状态:」などの固定項目が毎回入っているため、ルール文書（`docs/source-policy.md` など）より上位に来てしまいます。
`--source-type docs` を付けると正しくルール文書が返るため、「どの種類の資料を検索すべきか」を先に決めることが重要だと分かりました。

これまでの評価では `eval_questions.json` に正解の `source_types` を書いていましたが、実際のユーザーはそれを指定しません。そこで質問文から推定する `route_source_types` を追加しました。

## ルール（`rag/scripts/source_filters.py`）

| 優先度 | 条件 | 検索対象 |
|---|---|---|
| 1 | 字段 / 格式 / 规则 / 规范 / 流程 / 清单 / policy / format / checklist / schema を含む | docs |
| 2 | ルール系の語（AI Watchtower, 核对, 核验, 可信度, 怎么判断 など）だけを含む | docs |
| 3 | ニュース系の語（发布, 宣布, 推出, 权重, 模型, 新闻 など）だけを含む | current_news + history_news |
| 3' | さらに 最新 / 最近 / 今天 / 本周 を含む | current_news |
| 4 | 両方含む、またはどちらも含まない | 全 source（絞り込みなし） |

ルールベースにした理由: API コストがかからず、なぜその source を検索したのかを説明できるため。LLM による分類は後で比較対象として追加できます。

## 評価モード（`evaluate_demo.py --routing`）

| モード | source_types の決め方 | 意味 |
|---|---|---|
| `hint` | `eval_questions.json` に書いた値 | 上限値（正解の種別が分かっている場合） |
| `auto` | `route_source_types` の推定 | 実際の利用に近い値 |
| `none` | 絞り込みなし | ベースライン |

## ローカルでの結果（2026-09-30、5 問）

| backend | none | auto | hint |
|---|---|---|---|
| local-vector | 60% | 100% | 100% |
| local-keyword | 40% | 40% | 60% |

## 注意（過学習）

ルールは同じ 5 問を見ながら作ったため、`auto` の 100% は楽観的な数字です。評価質問を増やし（特にルールに合わない言い回しや、docs とニュースの両方にまたがる質問）、未知の質問での精度を確認する必要があります。

面接用: 「全 source を一律に検索すると、固定項目を多く含むニュースがルール文書を押しのける問題がありました。質問から検索対象を推定するルーティングを入れ、推定なし / 推定あり / 正解指定の 3 条件で評価して効果を切り分けました。ただし評価セットが小さいため、質問を増やして過学習していないか確認する予定です。」

## 25 問での再評価（2026-10-05）

評価セットを 25 問に増やし、ルールは変更せずに再評価しました。

| backend | none | auto |
|---|---|---|
| local-vector | 68%（MRR 0.55） | 72%（MRR 0.56） |
| azure-vector | **100%（MRR 0.87）** | 84%（MRR 0.74） |
| azure-hybrid | 92%（MRR 0.78） | 76%（MRR 0.75） |

- 言い換え 6 問のうち 4 問で、docs の質問に「新闻」「发布」が含まれるためニュースに誤ルーティングされ、正解の文書が除外された（例: 「已经发布的新闻数据出错了要怎么处理？」）。
- ハードフィルタは誤判定すると正解を完全に失う。実 embedding の検索では絞り込みなしの方が良い。

結論: Azure 検索の既定は `routing none`。ルーティングは弱い retriever の補助、または将来はハードフィルタではなくスコアの加点（ソフトブースト）として検討する。
